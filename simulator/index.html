Model, rate equations, and limits
Seven core variables
G GPU slots; λ jobs/min; K steps/job; N tokens/step; T seconds per 4,096 tokens; S seconds/switch; q steps before yielding.
One queue, three resources
FIFO ready jobs. Each worker holds one job for q steps. Every step uses serialized control service, shared bandwidth, then compute, transfer, and completion.
Compute model
t = T × N / 4096
dW/dt ≈ (λ/60)K − completed_steps/s
W is unfinished work in steps. Linear token scaling is a local approximation within one model and sequence-length regime.
Necessary load checks
a = λ/60
a(Kt + S) < G
aKC < 1
a(KNb + M) < B
C = control seconds/step; b = bytes/token; B = bytes/sec; M = state bytes/install. Every job pays at least one install. Repeated switches add traffic. Passing these checks does not prove stability: resources block each other.
Switching tradeoff
switch share ≈ S / (q·t + S)
This assumes a different job every turn. Longer turns amortize switching but make other jobs wait. Continuing the same job pays no new switch.
What is excluded
VRAM capacity and eviction, model mixtures, multi-GPU jobs, batching across jobs, failures, topology, and overlapping transfers. Optional client pauses happen between turns. Initial setup uses S; adapter switches and model reloads need separate profiles later.

Each job has independent, reproducible simulation draws. Jobs round to at least one step; this can raise the actual mean for tiny, highly variable jobs. Tokens and timing fluctuate around their means. The link is a single FIFO bandwidth resource, with 80% input and 20% output bytes. A worker remains occupied during its control/transfer waits. Throughput counts tokens from acknowledged steps, including steps of unfinished jobs. Runs stop at the horizon without silently draining unfinished jobs. Short-window completion rates have boundary effects. The scheduling policy here is a design experiment, not a claim about the current PR.
